# 6. Предпросмотр без GUI

## 6.1. Зачем

До интеграции с Blender/Qt нужно увидеть:

* как выглядят исходные и обработанные контуры;
* где сработали ограничения (радиус, угол, отклонение);
* что именно вернёт движок на конкретном запросе;
* как ведёт себя пайплайн при разных параметрах.

Поэтому предпросмотр — **отдельный пакет** `slicer_preview`, который читает
`ProcessingRequest` + `ProcessingResult` и пишет SVG/HTML. Он не импортирует
движок и не требует GUI. Это же делает его удобным для golden-тестов.

## 6.2. CLI

```bash
# result.json уже есть
python -m slicer_preview \
  --request examples/request.example.json \
  --result examples/result.example.json \
  --out preview/

# посчитать и отрисовать за один шаг
python -m slicer_preview \
  --request examples/request.example.json \
  --process \
  --out preview/

# только один срез, с точками и диагностикой
python -m slicer_preview \
  --request examples/request.example.json \
  --result examples/result.example.json \
  --slice s0 --points --out preview/s0.svg

# ASCII для терминала (без файлов)
python -m slicer_preview \
  --request examples/request.example.json \
  --result examples/result.example.json \
  --ascii 80
```

Флаги:

| Флаг | Смысл |
| --- | --- |
| `--request PATH` | входной запрос (обязателен) |
| `--result PATH` | готовый результат; иначе `--process` |
| `--process` | вызвать `slicer_engine` (если установлен) |
| `--slice ID` | только один срез |
| `--points` | рисовать вершины |
| `--tags` | подписывать теги сегментов |
| `--grid` | координатная сетка в мм |
| `--overlay` | наложить исходный и обработанный контуры |
| `--ascii N` | ASCII-рендер шириной N символов |
| `--out PATH` | файл `.svg` или каталог для `index.html` |

## 6.3. SVG: раскладка

Для каждого среза — панель. По умолчанию режим **«до / после / наложение»**:

```text
┌──────────────────────────────┬──────────────────────────────┐
│ Slice s0 — input             │ Slice s0 — output            │
│  ┌────────────────────────┐  │  ┌────────────────────────┐  │
│  │  outer (cut)           │  │  │  outer (cut)           │  │
│  │  ○ hole                │  │  │  ○ hole                │  │
│  │  ┄ fold (score)        │  │  │  ┄ fold (score)        │  │
│  └────────────────────────┘  │  └────────────────────────┘  │
├──────────────────────────────┴──────────────────────────────┤
│ metrics: points 12 → 24 · min R 8.0 mm · max turn 30°       │
│ diagnostics: 1 warning, 0 errors                            │
└─────────────────────────────────────────────────────────────┘
```

Режимы:

* `--overlay` — исходный контур серым пунктиром, результат цветом; так видно
  отклонение.
* `--points` — маленькие кружки; якоря/углы — крупнее.
* `--grid` — сетка с шагом 10 мм и подписями.
* Диагностика с координатой (`point_index`) подсвечивается красным кружком.

Цвета (`palette.py`):

| Элемент | Цвет |
| --- | --- |
| `cut` | `#1f77b4` (синий) |
| `score` | `#ff7f0e` (оранжевый), пунктир |
| `guide` | `#999999` (серый), тонкий |
| исходный контур | `#aaaaaa`, пунктир |
| `warning` | `#d6a000` |
| `error` | `#d62728` |
| заливка отверстия | полупрозрачная, even-odd |

## 6.4. Координаты и масштаб

* В контракте `y` направлен вверх. В SVG ось `y` направлена вниз, поэтому
  при рендере выполняется `y_svg = top + (max_y - y) * scale`.
* `viewBox` подбирается по объединённым границам всех контуров с отступом
  `margin = 8 мм` (в единицах модели).
* Масштаб — общий для всех панелей, чтобы срезы можно было сравнивать.
* Единицы в подписях — мм.
* Для очень больших координат (например, срез в 10 м) кадр уже локальный;
  дополнительное смещение не требуется.

## 6.5. HTML-контактный лист

`index.html` содержит:

* заголовок проекта, `request_id`, версии движка/протокола;
* таблицу срезов: id, индекс, число контуров, точки до/после, минимальный
  радиус, статус;
* inline SVG каждой панели (без внешних ресурсов);
* блок диагностики с фильтром по severity;
* легенду.

Всё генерируется строками/`html.escape`, без шаблонизаторов. Это важно для
стандартной библиотеки и безопасности: пользовательские строки (id, теги,
сообщения) экранируются.

## 6.6. ASCII-режим

Для быстрой проверки в терминале:

```text
s0  outer  cut   ••••••••••••••
    hole   cut        ····
    fold   score  ┄┄┄┄┄┄┄┄
```

Или растр: каждый символ — ячейка сетки; контур рисуется `#`, отверстие `o`,
линия сгиба `~`, ошибка `!`. Разрешение задаётся `--ascii N`. Это не заменяет
SVG, но полезно в CI/SSH.

## 6.7. Детерминизм и golden-тесты

* В SVG не должно быть текущего времени, абсолютных путей и случайных ID.
* Порядок элементов фиксирован: панели по `slice.index`, контуры по порядку в
  результате.
* Числа форматируются с фиксированной точностью (например, 3 знака).
* `preview/golden/` хранит эталонные SVG для набора запросов; тест сравнивает
  байты (или нормализованный SVG).
* Для сравнения «по смыслу» можно проверять bounding box, число точек, цвета
  ролей — но в v1 достаточно байтового сравнения при детерминированном
  рендере.

## 6.8. Что смотреть в примере

Файл [examples/preview.slice0.svg](examples/preview.slice0.svg) показывает:

* слева — исходный прямоугольник 60×40 мм, отверстие и линия сгиба;
* справа — результат после `fillet_corners` с радиусом 8 мм;
* внизу — метрики и предупреждение по второму срезу (тонкая стенка);
* серым пунктиром — исходный контур для сравнения.

По этому файлу уже можно оценить:

* как выглядят скругления и плотность точек;
* как отличить рез от линии сгиба;
* достаточно ли информативен результат для отладки.

## 6.9. Будущее

* интерактивный просмотрщик (pan/zoom, выбор контура) — отдельный лёгкий
  HTML/JS или Qt, но не в v1;
* рендер в PNG через стандартный `zlib` + `struct` (без Pillow) — возможно,
  но SVG проще и качественнее;
* 3D-просмотр стопки срезов — задача адаптера хоста, не `slicer_preview`.
