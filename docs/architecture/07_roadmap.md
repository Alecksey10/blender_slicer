# 7. План реализации и проверки

## 7.1. Принцип

Сначала — **данные и предпросмотр**, потом — алгоритмы, потом — хост.
Так можно увидеть конфиги, API и срезы до того, как появится GUI.

## 7.2. Этапы

### Этап 0. Контракт и витрина (без алгоритмов)

Цель: увидеть, «как это выглядит».

* [ ] `slicer_protocol`: dataclasses, enum, JSON-кодек, версии.
* [ ] `examples/request.example.json`, `result.example.json`,
      `preview.slice0.svg` как эталоны.
* [ ] `slicer_preview`: SVG-рендер, контактный лист, ASCII.
* [ ] `Engine.describe()` с заглушками методов (дескрипторы без реализации).
* [ ] Тесты: сериализация/десериализация, round-trip JSON, детерминизм SVG.

**Готово, когда:** пример запроса открывается в предпросмотре, SVG совпадает с
эталоном, а `describe` выдаёт корректную схему для GUI.

### Этап 1. Базовая геометрия

* [ ] `normalize`: дубликаты, замыкание, ориентация, вложенность.
* [ ] `validate`: инварианты, лимиты, конечность чисел.
* [ ] `resample`, `simplify`, `densify`.
* [ ] `fillet_corners` с режимами `clamp`/`error`/`skip`.
* [ ] Метрики: длина, min radius, max turn, отклонение.
* [ ] CLI: `describe`, `validate`, `process`.

**Готово, когда:** пример `request.example.json` даёт `result.example.json`
(с точностью до допусков), а SVG показывает скругления.

### Этап 2. Сглаживание и ограничения

* [ ] `smooth` (Chaikin + constrained Laplacian).
* [ ] `limit_curvature`.
* [ ] `local_recalc` с якорями и затуханием.
* [ ] `bend_check` (угол, радиус, bend allowance).
* [ ] Политики `strict`/`per_slice`/`best_effort`.
* [ ] Диагностика с координатами и `details`.

**Готово, когда:** можно обработать срез с острыми углами, получить warning о
невыполнимом радиусе и увидеть это в предпросмотре.

### Этап 3. Адаптер и GUI-контракт

* [ ] `slicer_adapters.base`: `CoordinateFrame`, `FrameStore`, `RuntimeState`,
      `EventBus`, `EngineClient`.
* [ ] `HostAdapter` Protocol и локальный `preview_adapter`.
* [ ] `ui.schema` + `Builder`/`Widget` Protocol.
* [ ] `AppController`: события → запрос → результат → инвалидация preview.
* [ ] `BlenderAdapter`: меш, плоскости, кадры, отображение.
* [ ] Проверка версий при старте.

**Готово, когда:** Blender-плагин строит срезы, отправляет запрос, получает
результат и рисует его; параметры GUI берутся из дескрипторов.

### Этап 4. Экспорт и удобство

* [ ] SVG-экспорт контуров реза (не только preview).
* [ ] DXF (ASCII) — простая полилиния, без внешних библиотек.
* [ ] Кеш результатов, отмена устаревших запросов.
* [ ] Undo/redo снимками состояния.
* [ ] Набор пресетов материалов/пайплайнов.
* [ ] Документация для пользователя.

**Готово, когда:** срез можно вырезать/сохранить и повторить результат по
сохранённому запросу.

## 7.3. Тестовая матрица

| Уровень | Что проверяем | Инструмент |
| --- | --- | --- |
| Контракт | JSON round-trip, defaults, unknown fields | `unittest`, golden JSON |
| Геометрия | расстояния, пересечения, кривизна, филет | unit-тесты на аналитических примерах |
| Инварианты | замкнутость, дубликаты, ориентация, вложенность | property-тесты на seeded `random` |
| Пайплайн | порядок этапов, селекторы, политики | табличные тесты |
| Детерминизм | одинаковый запрос → одинаковый результат | сравнение канонического JSON |
| Предпросмотр | SVG не содержит времени/путей | golden SVG |
| Round-trip | 3D→2D→3D в допуске | численный тест с разными кадрами |
| Производительность | 100k точек, линейные этапы | замер, без строгого порога в CI |
| Импорты | слои не нарушают зависимости | AST-скрипт |

Property-тесты без Hypothesis: генерируем случайные контуры seeded `random`,
проверяем инварианты и отсутствие исключений. Этого достаточно для v1.

### Аналитические примеры для филета

* прямой угол, радиус 8, segments 3 → известные точки дуги;
* очень короткий сегмент → `clamp`/`error`;
* turn 180° → радиус 0, угол не обрабатывается;
* замкнутый квадрат → 4 дуги, число точек предсказуемо;
* отверстие → ориентация CW после `normalize`.

### Проверка локального пересчёта

* диапазон в середине → точки вне диапазона не изменились побайтово;
* диапазон на границе замкнутого контура → корректный wrap;
* `blend_points` → нет излома на границе (проверка угла);
* пустой диапазон → `E_PARAM`.

## 7.4. Критерии готовности v1

1. Запрос из примера проходит `validate` без ошибок.
2. Результат совпадает с эталоном по точкам (допуск `1e-6` мм) и метрикам.
3. Предпросмотр открывается в браузере и показывает «до/после».
4. Ошибка в одном срезе не ломает остальные (`per_slice`).
5. Все числа конечны, нет `NaN` в JSON.
6. Движок не импортирует хост и не читает файлы.
7. Нет зависимостей вне стандартной библиотеки.
8. Повторный запуск даёт идентичный результат.
9. API-дескриптор достаточен, чтобы GUI построил форму без ручного кода.
10. Документация объясняет, как добавить метод и как собрать запрос.

## 7.5. Открытые вопросы

1. **Семантика min bend radius.** Это геометрическая кривизна контура
   (проволока/полоса) или радиус гиба листа в 3D? В v1 — кривизна 2D-контура и
   `bend_check` для линий сгиба. Полный 3D-unfold — отдельный модуль.
2. **Формулы vs точки.** Концепция упоминает «кривые в виде формул». В v1
   выход — точки; параметрические примитивы (`arc`, `spline`) — необязательное
   расширение. Нужно ли это Blender для редактируемых кривых?
3. **Локальный пересчёт.** Достаточно ли диапазона индексов + якорей, или нужны
   стабильные ID вершин между пересчётами? Если да — добавить `vertex_id` в
   отдельный параллельный массив.
4. **Отверстия и вложенность.** Всегда ли `parent_id` задаёт адаптер, или
   движок должен вычислять вложенность сам? В v1 — и то, и другое: адаптер
   может задать, `normalize` может вычислить.
5. **Единицы хоста.** Blender часто в метрах; нужен ли автоматический
   `host_units` → мм с коэффициентом в проекте? Да, но перевод делает адаптер.
6. **Керф и offset.** Компенсация реза — критична для лазера. В v1 её нет;
   нужен ли `offset` уже в v1 или можно отложить?
7. **Самопересечения.** Детектировать O(n²) или строить sweep line? Для v1 —
   детект с лимитом; автофикс отложен.
8. **Формат проекта.** JSON достаточен? Может понадобиться `.zip` с мешем/
   кадрами/результатами для переносимости.
9. **Blender-интеграция.** Срезы строятся средствами Blender (`bmesh`) или
   собственным пересечением? Влияет на точность и производительность.
10. **Экспорт.** SVG/DXF достаточно? Нужен ли G-code и какие параметры станка?

## 7.6. Что делать дальше

1. Утвердить контракт (особенно роли контуров, единицы, `frame_id`).
2. Сгенерировать/проверить примеры JSON и SVG.
3. Реализовать этап 0 (контракт + preview) — это даст «картинку» без GUI.
4. Реализовать этап 1 и прогнать на реальных срезах из Blender.
5. После стабилизации геометрии — адаптер и GUI.

Такой порядок минимизирует риск: сначала видно данные и результат, потом
пишется сложная геометрия, и только потом появляется GUI.
