# Дизайн движка срезов (v0.1)

Проектное предложение по **логическому движку**, контракту данных и способу
посмотреть результат до появления GUI.

Документ не является реализацией. Здесь описаны:

* границы ответственности и модульная архитектура;
* интерфейсы и формат обмена (Python + JSON);
* конфиги проекта, материала, пайплайна и GUI;
* поток данных от меша до готовых срезов;
* формат предпросмотра срезов без GUI (SVG/HTML);
* план реализации и критерии готовности.

## Быстрый взгляд на решения

| № | Решение | Почему |
| --- | --- | --- |
| D1 | Движок работает **только с 2D** (`x, y`, мм) | не зависит от ориентации среза и от хоста; 3D остаётся в адаптере |
| D2 | Движок **stateless**, все данные приходят в запросе | соответствует концепции; запрос воспроизводим, кеш принадлежит адаптеру |
| D3 | Единицы контракта: **мм и градусы**; углы внутри — радианы | одна точка перевода единиц — адаптер; материал задаётся в мм |
| D4 | `CoordinateFrame` — сущность **адаптера**, движок видит только `frame_id` | движок не знает о 3D; кадр можно хранить и версионировать отдельно |
| D5 | Контуры делятся по роли: `cut`, `score`, `guide`; открытые и замкнутые | лазерная резка, линии сгиба и вспомогательная геометрия — разные вещи |
| D6 | Пайплайн — **упорядоченный список операций** с параметрами | конфигурируется без кода, легко версионировать и показывать в GUI |
| D7 | Запрос **самодостаточен**: материал, операции и срезы внутри | движок не читает файлы и не зависит от проекта; удобно для RPC и тестов |
| D8 | Обмен — обычный **JSON + `dataclasses`** из стандартной библиотеки | без pydantic; схемы и валидация описываются декларативно |
| D9 | Основной выход — **плотная полилиния**; формулы/примитивы — опционально позже | предсказуемо для экспорта и визуализации; формулы можно добавить как метаданные |
| D10 | Локальный пересчёт — по `(slice_id, contour_id, range)` + якоря | не требует глобальных ID вершин и переживает перестройку результата |
| D11 | Ошибки не бросаются через границу: `ProcessingResult.status` + диагностика | GUI и адаптер получают частичный результат вместо падения |
| D12 | Предпросмотр — отдельный пакет, генерирующий **SVG/HTML** | стандартная библиотека, открывается в браузере/VS Code, не требует GUI |
| D13 | Отступ — **геометрия движка**: `Slice.offset_mm` (+ наружу) и метод `offset_contour` | отступ меняет контур, а не отображение; результат воспроизводим и тестируем без хоста |
| D14 | Политика отступа по осям — в адаптере (`CutOffsetPolicy`): X наружу, Z внутрь, Y нет | правило «какой проход снаружи» зависит от проекта, а не от алгоритма |
| D15 | Минимальный отступ = `thickness/2 + kerf` | это радиус сечения материала: соседние детали не пересекаются и годятся под сварку |
| D16 | Контакты — пакет `spatial`, расчёт в 3D через `CoordinateFrame` | срезы хранятся в 2D, но встречаются в 3D; движок остаётся 2D |
| D17 | Итерации срезов — слои (`SliceLayer`/`LayerStore`) в адаптере | X- и Z-проходы видны вместе, у каждого свой цвет, видимость и результат |
| D18 | Многопоточность решает **клиент**, движок исполняет чанками | хост знает свои ограничения; `STRICT` остаётся последовательным |
| D19 | Ужимание сечений — метод `shrink_section`, распределение по слоям — `SectionShrinkPolicy` | широкие трубы/провода ужимаются плавно, без ступенек; движок владеет геометрией |
| D20 | Локализация — каталог `i18n/` + регистрация в `bpy.app.translations` | панели следуют языку Blender, каталог тестируется без GUI |

## Что считается v1

**Входит:**

* нормализация и валидация контуров;
* `fillet_corners`, `smooth`, `simplify`, `resample`, `densify`;
* проверка минимального радиуса/угла и отклонения;
* пакетная обработка нескольких срезов;
* частичные ошибки и диагностика;
* JSON-контракт и CLI;
* SVG-предпросмотр «до/после» и контактный лист.

**Добавлено в 0.3.0:**

* отступ срезов в движке (`offset_contour`, `Slice.offset_mm`) и политика
  осей в адаптере (`CutOffsetPolicy`);
* точки соприкосновения (`spatial/contacts.py`);
* слои итераций (`SliceLayer`/`LayerStore`) и совместная визуализация;
* многопоточная обработка на клиенте с последовательным fallback.

**Не входит в v1 (точки расширения):**

* пересечение меша с плоскостями — это делает хост;
* полноценный 3D-unfold и сборка модели — адаптер/будущий 3D-модуль;
* булевы операции и dogbone (offset реализован в 0.3.0);
* автоматическое устранение самопересечений (в v1 — только обнаружение);
* GUI и экспорт в DXF/G-code (кроме SVG-предпросмотра);
* внешние библиотеки (`numpy`, `shapely`, `pydantic` и т.п.).
