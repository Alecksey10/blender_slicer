### Интерфейсы к GUI

## GUI Adapter/Proxy
Для некоторой версионности GUI и возможности не переписывать много кода, можно установить некоторые базовые пути общения бекенда и окружения за счёт GUI.
Adapter будет работать с различными клиентами, например, Blender GUI и т.д.

### Требования
* Должна быть конфигурация для построения GUI. Каждое окружение должно строить этот GUI.
* Должна быть конфигурация и типизация для внутренних 
* Адаптация к базовым методам/ручкам, методы и ручки можно расширять просто за счёт предоставления к ним доступа и конфигурации. Какие данные подавать и как их обрабатывать 

# Другими словами

## Общий Pipeline

* У нас есть абстрактная среда с GUI, будь то Blender, Unreal engine, QT GUI и прочие
    * Эти среды позволяют запускать собственные плагины
    * У плагинов должна быть возможность хранить некоторые данные в оперативной памяти/глобальных переменных аддона
* Мы создаём какой-нибудь Mesh
* Настраиваем плагин на работу, в частности, генерируем срезы:
    * выбираем центр срезов
    * Направление срезов, например:
        * круговое направление плоскостью из центра
        * или множество плоскостей, идущих поперёк некоторой оси (то есть горизонтальные/вертикальные срезы)
* Сама среда генерирует срезы и ключевые точки
* Настраиваем плагин на работу, подаём срезы 
    * Изначально каждый срез представляет собой ключевуые точки в пространстве
    * При подаче каждый срез переводится в двухмерную плоскость для удобства обработки, при этом запоминается правило перевода
    * Происходит запрос на обработку каждого среза движком согласно заданным параметрам 
    * Движок генерирует новые точки для срезов (можно для каждого среза отдельно)
* Движок возвращает точки
    * Среда разворачивает точки каждого среза, как было запомнено до этого
    * Движок визуализирует новые, сглаженные срезы
* Далее срезы можно сохранить в печатаемый вид, можно передать в другое приложение на дальнейшую доработку, например, для совмещения печати.
