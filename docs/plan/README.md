# Концептуальный план модульного развития

Статус: рабочий план. Версия 0.1, 2026-11-11.

Документ задаёт направление рефакторинга и порядок работ. Он не описывает
каждый алгоритм: детали остаются в `docs/architecture/`, а требования к
средам — в `docs/requirements/`.

## 1. Цель

Сделать ядро срезов переносимым между Blender, FreeCAD, CLI и HTTP API без
копирования логики. Один и тот же 2D-алгоритм должен давать одинаковый
результат во всех средах, а разница должна оставаться только в адаптере:
получение меша, плоскости, кадры координат и отображение.

Ключевая метрика — **минимум дублирования**: у каждого понятия один
владелец, у каждого контракта одна реализация, у каждого поля одно место
описания.

## 2. Принципы

1. **Ядро не знает о хосте.** `protocol`, `engine`, `spatial` не импортируют
   `bpy`, `FreeCAD`, `Part`, `Qt` и не читают файлы.
2. **Адаптер — тонкий.** Он переводит настройки хоста в `SlicePlan` и
   `ProcessingRequest`, режет меш, рисует результат и хранит состояние
   сессии. Геометрию он не переписывает.
3. **Один источник истины.** Формула радиуса, допуск, шаг, лимиты и
   единицы живут в одном модуле; адаптеры и UI не повторяют их.
4. **Композиция вместо флагов.** Этап — это метод движка с параметрами и
   `enabled`; адаптер только собирает упорядоченный список операций.
5. **Стабильный фасад.** Внутренние модули можно дробить, но публичные
   импорты (`protocol.geometry`, `engine`, `adapters.base`) остаются
   совместимыми через `__init__.py`.
6. **Тестируемость без хоста.** Любой модуль ядра проверяется на чистом
   Python; адаптер — через фейковый хост.
7. **Ошибки — данные.** Движок возвращает диагностику, а не падает через
   границу; адаптер решает, как её показать.

## 3. Целевая карта модулей

| Слой | Модуль | Ответственность |
| --- | --- | --- |
| Контракт | `protocol/` | dataclasses, единицы, JSON, ошибки, дескрипторы |

| Геометрия | `protocol/geometry/intersections.py` | точка в полигоне, самопересечения |
| Геометрия | `protocol/geometry/resampling.py` | `resample`, `densify` |
| Геометрия | `protocol/geometry/simplification.py` | Дуглас–Пекер, острые углы |
| Геометрия | `protocol/geometry/smoothing.py` | Chaikin, Laplacian, limit curvature |
| Геометрия | `protocol/geometry/corners.py` | коллинеарность, филлет, обрезка тесных углов |

| Геометрия | `protocol/geometry/sheet.py` | допуск гиба |
| Геометрия | `protocol/offset.py` | отступ контура |
| Движок | `engine/` | реестр методов, пайплайн, валидация, фасад |
| Хост-база | `adapters/base/` | `SlicePlan`, контроллер, слои, события, UI-схема |
| Blender | `adapters/blender/` | `bpy`, меш, кривые, панели, операторы |
| FreeCAD | `adapters/freecad/` (план) | `FreeCAD`, `Part`, `Draft`, Qt-панель |

Границы зависимостей:

```
protocol  <-  engine  <-  adapters/base  <-  adapters/<host>
     ^            ^              ^
     +-- spatial -+              +-- preview
```

`spatial` использует только `protocol` и стандартную библиотеку.

## 4. Контракт хоста

Каждый адаптер реализует один и тот же порт (подробно —
`docs/requirements/host_environments.md`):

```python
class HostAdapter(Protocol):
    name: str

    def slice_mesh(self, plan: SlicePlan) -> tuple[list[Slice], dict[str, CoordinateFrame]]: ...
    def show_layers(self, layers: list[SliceLayer]) -> None: ...
    def show_contacts(self, contacts: list[ContactPoint]) -> None: ...
    def clear_visuals(self) -> None: ...
```

Обязанности адаптера:

* получить меш в мировых координатах;
* пересечь его плоскостями согласно `SlicePlan`;
* собрать сегменты в замкнутые/открытые цепочки;
* перевести 3D-точки в локальный 2D-кадр (`CoordinateFrame`) в мм;
* вызвать `AppController`/`Engine` и вернуть результат в 3D;
* нарисовать слои и контакты средствами хоста;
* хранить состояние сессии (слои, кадры, ревизию) в памяти аддона.

Обязанности ядра: нормализация, все методы обработки, метрики,
диагностика, JSON-контракт, предпросмотр.

## 5. Этапы работ

### P0. Разделить геометрию по ответственности (выполнено)

`protocol/geometry.py` разбит на пакет из небольших модулей. Публичный
импорт `blender_slicer.protocol.geometry` сохранён: тесты и движок не
меняются. Критерий: все тесты проходят, `compileall` чистый, сборка архива
успешна.

### P1. Убрать дублирование в адаптере (выполнено)

* общий помощник `_operation(...)` для `OperationSpec`, чтобы не повторять
  `TargetSelector(roles=(CUT,))` в каждом блоке;
* общий помощник `emit_warnings(...)` в `engine/methods/base.py` для
  преобразования словарей геометрии в диагностику (используют
  `cut_thin_sections` и `trim_tight_corners`).

Критерий: меньше повторяющихся строк, поведение и тесты не меняются.

### P2. Один источник описания настроек

Сейчас `properties.py`, `ui_schema.py`, `settings_io.py` и
`fake_blender.py` перечисляют поля независимо. План:

* ввести declarative-таблицу `SettingSpec` (имя, тип, default, диапазон,
  секция, видимость, экспорт);
* генерировать из неё `ui_schema`, `settings_io` и проверки покрытия;
* `properties.py` оставить статическим (Blender RNA требует реальных
  `bpy.props`), но сверять с таблицей тестом.

Критерий: добавление настройки — одна запись в таблице плюс RNA-свойство,
а не четыре правки.

### P3. Формализовать контракт хоста тестами

* протокол `HostAdapter` в `adapters/base/host.py` (typing.Protocol);
* общий набор тестов `tests/contract/test_host_contract.py`, который
  прогоняется на Blender-фейке и будущем FreeCAD-фейке;
* запрет импортов хоста из ядра — тест архитектуры.

Критерий: новый адаптер подключается без изменения ядра.

### P4. FreeCAD-адаптер

* `adapters/freecad/slicing.py`: `Part.Shape.tessellate`, пересечение
  плоскостью, цепочки;
* `adapters/freecad/frames.py`: `FreeCAD.Vector`/`Placement` ↔
  `CoordinateFrame`;
* `adapters/freecad/visualization.py`: `Part.makePolygon`, `Draft`-объекты
  или `App::FeaturePython`;
* `adapters/freecad/panel.py`: Qt-панель, читающая `ui_schema`;
* `adapters/freecad/settings.py`: `App::Property` + сериализация в JSON.

Критерий: куб режется, филлет и автошаг работают, результат совпадает с
Blender на одном и том же запросе.

### P5. Объединение пересекающихся стадий в UI

* `Cut thin sections` + `Trim tight corners` → один раздел `Thin parts`;
* `Densify` + `Resample` → `Point spacing`;
* `Smooth` + `Limit curvature` → `Smoothing`;
* один радиус по умолчанию, пресеты, сводка активных стадий.

Критерий: меньше подпанелей, нет двух полей для одного понятия.

## 6. Ближайший технический долг

| Долг | Где | Решение |
| --- | --- | --- |
| Списки полей в четырёх местах | `properties`, `ui_schema`, `settings_io`, `fake_blender` | P2 |
| Похожие блоки `OperationSpec` | `adapters/blender/adapter.py` | `_operation` (P1) |
| Дубли диагностики | `cut_thin.py`, `trim_tight.py` | `emit_warnings` (P1) |
| Разные «радиусы» | Fillet, Trim, Limit curvature, материал | P5 |
| Нет протокола хоста | `adapters/base` | P3 |

## 7. Критерии готовности рефакторинга

1. `python3 -m unittest discover -s tests -t .` — все тесты зелёные.
2. `python3 -m compileall -q blender_slicer tools tests` — без ошибок.
3. `python3 -m blender_slicer.engine.cli describe` перечисляет все методы.
4. Ядро не импортирует `bpy`, `FreeCAD`, `Part`, `PySide`.
5. Новый адаптер может быть добавлен без правок `engine/` и `protocol/`.
6. Сборка `dist/blender_slicer-0.3.0.zip` успешна.

## 8. Риски

* Разделение геометрии может изменить порядок импортов; лечится
  реэкспортом в `geometry/__init__.py` и тестами.
* FreeCAD и Blender по-разному триангулируют меш; контракт фиксирует
  только 2D-результат, поэтому расхождения допустимы в пределах допуска.
* Перенос описания настроек в таблицу может сломать RNA-регистрацию;
  поэтому `properties.py` остаётся статическим до отдельного этапа.
