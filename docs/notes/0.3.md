# 0.3: замечания и статус

Исходные формулировки пользователя (README.md, раздел 0.3). Сам README не
правится: по договорённости заметки живут здесь.

| № | Замечание | Статус |
| --- | --- | --- |
| 1 | выделение жирными точками пересечений | сделано: контакты рисуются объёмными маркерами (октаэдры с материалом), пересечения — красные, близкие — оранжевые |
| 1.1 | контакты находятся ненормально, их должно быть больше | исправлено: на пару контуров возвращаются **все** точки пересечения (с дедупликацией), а не одна ближайшая |
| 2 | сечения должны ужиматься для широких труб/проводов, сохраняя гибкость и плавность | сделано: метод движка `shrink_section` + политика по слоям + сглаживание |
| 3 | разные языки, система локализации | сделано: каталог `ru/en`, `t()`, регистрация в `bpy.app.translations` |

## 1. Контакты

Было: `_contacts_between_layers` перебирал пары контуров и оставлял **одну**
ближайшую пару сегментов. Для скрещивающихся проходов (X и Z) этого мало:
линия пересечения даёт несколько точек, а на плотных контурах часть из них
терялась. Плюс маркеры были эмпти 0.5 мм — практически невидимые.

Главная причина, почему контактов «не было»: `BlenderHost.show_contacts`
выходил сразу, если выключена настройка **Build result curves**. То есть
поиск считался, но маркеры вообще не создавались. Кроме того, эмпити 0.5 мм
терялись на фоне модели, а кэш меша не учитывал изменение размера маркера.

Стало:

* контакты рисуются **всегда**, независимо от `build_curves`; при выключенных
  кривых `show_layers` очищает только коллекции слоёв и не трогает контакты;
* имя кэшированного меша включает радиус, поэтому смена размера маркера
  работает; старые неиспользуемые меши удаляются;
* радиус — `max(contact_marker_mm, 0.5% габарита модели)`, т.е. на 2-метровой
  модели маркер сам увеличивается; значение по умолчанию — 5 мм;
* кнопка **Frame Contacts** выделяет маркеры и приближает их в вьюпорте;
* `spatial/contacts.py` собирает все пересечения сегментов
  (`distance <= 1e-6`), сортирует по расстоянию и склеивает точки ближе
  `merge_mm` (по умолчанию 0.25 мм);
* если пересечений нет, возвращается одна ближайшая пара — параллельный проход
  не заливает сцену лишними точками;
* у `ContactPoint` появилось поле `kind`: `intersection` или `near`;
* параметры `find_contacts(..., merge_mm=0.25, max_per_pair=64, max_contacts=2000)`;
  плотные контуры (>160 сегментов) прореживаются по сегментам, чтобы поиск
  оставался интерактивным;
* `adapters/blender/visualization.py` создаёт **объёмные маркеры**: октаэдры
  с материалом, `show_in_front`. Цвет: пересечение — красный, близкий
  контакт — оранжевый. В кастомных свойствах объекта остаются расстояние,
  слои, срезы и тип.

Использование: включить **Contacts**, задать зазор, нажать **Find Contacts**
(или **Process Slices** — контакты ищутся после обработки автоматически).
Если маркеры не видны в кадре — **Frame Contacts**.

## 2. Ужимание сечений

Задача: широкие трубы/провода должны становиться уже, но без ступенек и
изломов, чтобы деталь оставалась гибкой и плавной.

Разделение ответственности то же, что у отступов:

* **адаптер** решает, насколько ужать каждый срез: `SectionShrinkPolicy`
  (`adapters/base/plan.py`) кладёт `shrink_ratio` в `Slice.metadata`;
* **движок** применяет коэффициент и сглаживает результат методом
  `shrink_section` (`engine/methods/shrink.py`, `protocol/shrink.py`).

Профили (`shrink_mode`):

| Профиль | Что делает |
| --- | --- |
| `UNIFORM` | все сечения ужимаются на один процент |
| `MIDDLE` (по умолчанию) | плавный taper: концы не тронуты, середина ужата по синусоиде |
| `ENDS` | зеркально: ужаты концы, середина не тронута |

Настройки: `shrink_enabled`, `shrink_percent` (0–90), `shrink_mode`,
`shrink_smooth_iterations` (0–10, по умолчанию 2). Операция `shrink_section`
ставится первой, до отступов, филета и сглаживания. Внутри метода:

1. `shrink_points` масштабирует точки к центру масс (или центру bbox);
2. `laplacian` сглаживает результат, сохраняя острые углы
   (`preserve_corners_deg`);
3. слишком маленький коэффициент (≤ 0.01) не применяется — выдаётся
   `E_CONSTRAINT_UNSATISFIED`, контур остаётся прежним.

## 3. Локализация

* `blender_slicer/i18n/` — чистые данные и `t(msgid, locale=None, **kwargs)`;
* `SUPPORTED_LOCALES = ("en", "ru")`, `normalize_locale` понимает `ru_RU`,
  `ru-RU`, `en_US` и т.п.;
**Как это работает.** Язык берётся из самого Blender: `Edit → Preferences →
Interface → Translation → Language`. Отдельного переключателя в плагине нет
намеренно — иначе язык плагина и язык остального интерфейса разъезжаются.
Текущий язык виден в панели **About** («Interface language: ru»).

* статические подписи (`layout.label`, заголовки панелей, кнопки) больше не
  остаются английскими: весь текст идёт через `tr()` → `t()` с текущей
  локалью Blender;
* подписи полей берутся из схемы (`ui_schema`) или из RNA-имени свойства и
  тоже проходят через `tr()`;
* `adapters/blender/i18n.py` дополнительно регистрирует каталог в
  `bpy.app.translations` — на случай, если Blender сам захочет перевести
  RNA-строки;
* неизвестные строки возвращаются как есть, английский — identity-каталог.

Важно: без перезагрузки Blender язык не меняется (это ограничение самого
Blender, а не плагина). Если интерфейс остался английским — проверьте, что в
настройках выбран русский язык и плагин переустановлен из нового архива.

Ограничение: динамические статусы (`Generated 20 slices`) и диагностика
движка пока остаются на английском; они формируются в движке, у которого нет
локали. Каталог расширяется без изменения кода панелей.

## Как проверить

```bash
python3 -m unittest discover -s tests -t .     # 185 тестов
python3 -m blender_slicer.engine.cli describe | grep shrink_section
```

В Blender: куб → **Run** для оси Z, затем для X; включить **Contacts** и
**Find Contacts** — маркеров должно быть много (каждая пара пересекающихся
срезов даёт свои точки). Включить **Section shrink**, профиль `MIDDLE`:
середина стека уже, концы прежние, переход плавный. Язык интерфейса — в
`Edit → Preferences → Interface → Translation → Language → Russian`.

Не проверено вживую: визуальный размер маркеров и перевод панелей требуют
запущенного Blender; в Python-тестах проверены только данные и геометрия.
