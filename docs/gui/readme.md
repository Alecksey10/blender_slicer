
## GUI окружение

Есть стандартные виджеты (кнопки, текстовые поля, отображение значений, связь между ними)
GUI Config подразумевает:
* возможность вызова перерасчёта отображаемого
    * например, при при изменении выбранных параметров
* вызов событий.
    * При этом где-то будет обработчик событий, который реализует по большей части всю логику

### Управляющий ЖЦ GUI. Main.py? 

* Появляется при инициализации плагина
* Подгружает все доступные функции (через какой-нибудь другой класс, например, с реестром функций)
* Собирает данные GUI конфигурации функций
* Подготавливает [обработчик GUI](#обработчик-событий)
    * 

### Построитель GUI. 
(по идее это базовый класс, а его на самом деле реализует тот класс, который подходит под текущее окружение, например, Blender или браузер. он должен связываться со внешнем)
* Получает данные из конфигурации. 
* Строит кнопки, виджеты, layouts, отступы, разделения и т.д.

#### Элементы GUI и данные
Данные должны соответствовать некоторым стандартам, наверно, например, старое значение и новое.
Элементы GUI также, например, изменяемые должны реализовывать on_change, current_value и т.д., чтобы я мог с ними общаться через общие интерфейсы.
При этом должны быть общие события, например, на изменение интерфейса


### Обработчик событий
Допустим, будет несколько классов для реализации системы событий с подписками (всё на python).
Например, постоянно будут генерироваться события на изменение переменных, если обработчиков не будет - будут игнорированы. 
Могут идти дополнительные события логики, например, привязанные события на нажатие кнопок или определённые показатели параметров.
Например, при выборе какого-нибудь choosebutton будет строиться несколько отличающаяся конфигурация

#### Хранитель основной логики
При этом будет класс, который реализует всю основную бизнес-логику, на события в этом классе вызывают соответствующие методы, а затем будет вызываться логика на обновление GUI в приложении. 


## Память
Коли у нас будет окружение с доступом к Python, пусть будет некоторое хранилище + хранилище состояний для лучшего перехода между состояниями за счёт отдельных внутренних событий.
